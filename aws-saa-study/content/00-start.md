#### 왜 클라우드가 필요한가

1. 웹 서비스를 하려면 서버, 저장 장치, 네트워크 장비가 필요합니다. 예전에는 이 장비를 직접 사서 데이터 센터에 두었습니다. 사는 데 몇 주가 걸리고, 사용자가 몰릴 때를 대비해 넉넉히 사 두면 평소에는 놀게 됩니다.
2. **클라우드 컴퓨팅**은 이 장비를 인터넷으로 필요한 만큼 빌려 쓰고 쓴 만큼 내는 방식입니다. 몇 분 만에 서버 100대를 빌렸다가 1시간 뒤에 돌려줄 수 있습니다.
3. **AWS(Amazon Web Services)**는 이런 장비와 그 위의 관리 기능을 200개가 넘는 서비스로 빌려주는 회사입니다. 서버는 EC2, 저장소는 S3, 데이터베이스는 RDS처럼 서비스마다 이름이 있습니다.

SAA(Solutions Architect – Associate) 시험은 이 서비스들을 **조합해 요구 사항에 맞는 구조를 설계하는 능력**을 묻습니다. "주문이 몰려도 멈추지 않고, 가장 싸게, 운영 일은 적게"처럼 조건이 붙은 상황에서 가장 알맞은 조합을 고르는 문제가 대부분입니다.

#### 한 장으로 보는 용어 지도

바깥에서 안쪽으로 읽으면 됩니다. AWS는 전 세계에 **리전**(데이터 센터가 모인 지역)을 두고, 리전 안에는 서로 떨어진 **가용 영역(AZ)**이 여러 개 있습니다. 내 서비스는 리전 안에 **VPC**라는 나만의 네트워크를 만들고, AZ마다 **서브넷**을 나눠 **EC2**(가상 서버)와 **RDS**(관리형 데이터베이스)를 둡니다. 사용자의 요청은 **Route 53**(DNS)으로 주소를 찾고, **CloudFront**(엣지 캐시)를 거쳐, **ALB**(로드 밸런서)가 여러 EC2에 나눠 줍니다. 파일은 VPC 밖의 **S3**에 두고, 누가 무엇을 할 수 있는지는 **IAM**이 정합니다.

아래 번호는 요청 하나가 처리되는 순서입니다.

1. 사용자의 브라우저가 Route 53에 `www.example.com`의 주소를 묻습니다.
2. 받은 주소로 가장 가까운 CloudFront 엣지에 요청합니다. 이미지 같은 정적 파일은 엣지 캐시나 S3에서 바로 나갑니다.
3. 캐시할 수 없는 요청은 리전의 ALB로 갑니다.
4. ALB가 두 AZ의 EC2 중 건강한 곳으로 나눠 보냅니다.
5. EC2가 RDS 주 DB를 읽고 씁니다. 주 DB는 다른 AZ의 대기 DB로 동기 복제되어, AZ 하나가 멈춰도 대기 DB가 이어받습니다.

#### 문제에서 자주 쓰는 말

SAA는 시나리오 문제입니다. 서비스 이름보다 **조건을 뜻하는 말**을 먼저 알아 두면 문제를 빨리 읽습니다. 자세한 대응은 [문제 속 키워드로 답 고르기](#x-keywords)에 있습니다.

| 문제의 말 | 뜻 | 먼저 떠올릴 것 |
|---|---|---|
| 가장 비용 효율적인(MOST cost-effective) | 요구를 만족하는 것 중 가장 싼 것 | 스팟, S3 수명 주기, 서버리스 |
| 운영 오버헤드가 가장 적은(LEAST operational overhead) | 사람이 관리할 일이 가장 적은 것 | 관리형·서버리스 서비스 |
| 고가용성(highly available) | 일부가 고장 나도 계속 동작 | 다중 AZ |
| 내결함성(fault-tolerant) | 고장이 나도 성능 저하 없이 계속 동작 | 여유분을 미리 둔 다중 AZ |
| 느슨한 결합(decouple) | 구성 요소끼리 직접 부르지 않음 | SQS, SNS, EventBridge |
| 코드 변경 최소(minimal code changes) | 앱을 거의 안 고치고 옮김 | 같은 엔진의 관리형 서비스 |

#### 영어 이름과 한국어 공식 표기

시험은 한국어로 볼 수 있지만 서비스 이름은 영어 그대로 나옵니다(예: Amazon SQS). 기능 이름은 AWS 한국어 문서의 번역어가 쓰입니다. 이 학습서도 공식 표기를 따릅니다.

| 영어 | 한국어 공식 표기 |
|---|---|
| Availability Zone | 가용 영역 |
| Security group / Network ACL | 보안 그룹 / 네트워크 ACL |
| Read replica / Multi-AZ deployment | 읽기 전용 복제본 / 다중 AZ 배포 |
| Launch template / Scaling policy | 시작 템플릿 / 조정 정책 |
| Lifecycle configuration | 수명 주기 구성 |
| Visibility timeout / Dead-letter queue | 가시성 제한 시간 / 배달 못한 편지 대기열 |
| Presigned URL | 미리 서명된 URL |
| Customer managed key | 고객 관리형 키 |

@topic start-exam | SAA-C03 시험은 어떻게 진행되나
AWS Certified Solutions Architect – Associate(시험 코드 SAA-C03)는 AWS 서비스로 **안전하고, 복원력 있고, 성능 좋고, 비용 효율적인** 구조를 설계하는 능력을 검증하는 시험입니다. 2022년 8월 30일부터 C03 버전이 쓰이고 있고, 2026년 10월 현재 AWS는 다음 버전을 발표하지 않았습니다.

#### 시험 형식

| 항목 | 내용 |
|---|---|
| 문항 | 65개 (점수에 들어가는 50개 + 비채점 문항 15개) |
| 시간 | 130분 |
| 유형 | 객관식(보기 4개 중 1개), 복수 응답(보기 5개 이상 중 2개 이상) |
| 점수 | 100–1,000점 환산 점수, **720점 이상 합격** |
| 응시료 | 150 USD (환율·세금에 따라 원화 금액이 달라짐) |
| 응시 방식 | Pearson VUE 테스트 센터 또는 온라인 감독 시험 |
| 언어 | 한국어 포함 10개 언어 |
| 유효기간 | 3년 (같은 시험의 최신 버전이나 Professional 합격으로 갱신) |

- 비채점 15문항은 어느 문항인지 표시되지 않습니다. 모든 문항을 똑같이 풉니다.
- 답을 비워 두면 틀린 것으로 처리되고, 틀려도 감점은 없습니다. **모르는 문제도 반드시 고릅니다.**
- 영역별 합격선은 없습니다(보상형 채점). 전체 점수만 720점을 넘으면 됩니다.
- 시험 중 문항에 **검토 표시**를 해 두고 마지막에 다시 볼 수 있습니다.

#### 출제 영역과 비중

| 영역 | 비중 | 무엇을 묻나 |
|---|---|---|
| 1. 보안 아키텍처 설계 | 30% | IAM, 다중 계정, VPC 보안, 암호화, 키 관리 |

#### 시험 날의 흐름

1. AWS Certification 계정(aws.training)에서 시험을 예약합니다. 이때 언어와 응시 방식(센터·온라인)을 고릅니다.
2. 테스트 센터는 30분쯤 일찍 가서 신분증을 확인하고 소지품을 맡깁니다. 정부 발행 신분증과 보조 신분증이 필요하고, 영문 이름이 계정 이름과 맞아야 합니다. 후기들은 여권과 영문 이름이 있는 카드를 챙겼다고 적었습니다.
3. 130분 동안 문제를 풉니다. 센터에서는 필기용 보드나 종이를, 온라인 시험에서는 화면 속 메모장을 씁니다.
4. 결과는 공식적으로 5영업일 안에 계정에 올라옵니다. 2026년 후기들은 대부분 당일 저녁(시험 후 5~12시간)에 메일을 받았습니다.

#### 알아 둘 규정

SAA는 실기 시험이 아니지만, 콘솔에서 VPC, EC2, S3를 직접 한 번 만들어 보면 문제의 장면이 훨씬 빨리 그려집니다. 강의의 "Hands On" 레슨도 이 실습을 따라 합니다. 다만 AWS 계정은 실제로 돈이 나가는 계정이라, 시작 전에 몇 가지를 꼭 해 둡니다.

#### 계정을 만들면 바로 할 일

1. **루트 사용자에 MFA를 겁니다.** 루트 사용자는 모든 권한을 가진 사용자라, 비밀번호만으로 지키면 위험합니다([4.1](#c04-iam)).
2. **일상 작업용 IAM 사용자(또는 Identity Center 사용자)를 만듭니다.** 루트 사용자로는 결제와 계정 설정만 합니다.
3. **예산 알림을 만듭니다.** Billing의 Budgets에서 *Zero spend budget*(1센트라도 쓰면 알림)이나 월 예산을 만들어 이메일 알림을 받습니다. 강의 5장의 첫 레슨(AWS Budget Setup)이 이 작업입니다.
4. **실습 리전을 하나로 정합니다.** 리전마다 자원이 따로 보이므로, 실습한 리전을 기억해 두어야 정리할 때 빠뜨리지 않습니다.

#### 프리 티어와 크레딧

2025년 7월 15일 이후 새로 만든 계정은 프리 티어가 크레딧 방식으로 바뀌었습니다. 가입할 때 100 USD 크레딧을 받고, EC2·RDS·Lambda·Budgets 같은 서비스를 처음 써 보는 활동을 하면 최대 100 USD를 더 받습니다. 가입할 때 무료 플랜과 유료 플랜 중 하나를 고릅니다. 무료 플랜은 6개월이 지나거나 크레딧을 다 쓰면 끝나고, 유료 플랜으로 올리지 않으면 유예 기간 뒤 계정이 닫힙니다. 그 전에 만든 계정은 예전 프리 티어(12개월 무료 사용량) 규칙을 따릅니다. 실습 전 결제 콘솔에서 내 계정이 어느 쪽인지 확인하세요.

#### 실습 후 꼭 지울 것

| 자원 | 놔두면 생기는 일 |
|---|---|
| NAT 게이트웨이 | 트래픽이 없어도 시간당 요금이 나갑니다 |
| 탄력적 IP, 공인 IPv4 | 공인 IPv4는 쓰는 동안 시간당 요금이 붙습니다 |
| RDS, Aurora, ElastiCache | 인스턴스가 켜져 있는 동안 계속 과금됩니다 |
| EBS 볼륨과 스냅샷 | 인스턴스를 지워도 따로 남는 볼륨·스냅샷은 과금됩니다 |
| 로드 밸런서 | 대상이 없어도 시간당 요금이 나갑니다 |

> **주의** 키 파일(.pem)과 액세스 키를 코드 저장소나 블로그에 올리지 마세요. 공개 저장소에 올라간 키는 몇 분 안에 자동 수집돼 암호화폐 채굴에 쓰입니다.

@analogy
AWS 계정은 **진짜 돈이 나가는 가게 카드**예요. 그래서 처음에 세 가지를 꼭 해요.

1. 사장님 만능 열쇠(루트 사용자)에 지문 잠금(MFA)을 걸어요.
2. 매일 쓰는 직원 출입증(IAM 사용자)을 따로 만들어요. 만능 열쇠는 금고에 넣어 둬요.
3. "한 달에 이만큼 넘게 쓰면 알려 줘" 하는 알림(예산)을 걸어요.

실습이 끝나면 빌린 물건을 꼭 돌려줘요. 특히 **나가기 전용 쪽문(NAT 게이트웨이)**과 **기록실(RDS)**은 아무도 안 써도 켜져 있는 동안 돈이 나가요.

| 가게 | AWS |
|---|---|
| 사장님 만능 열쇠 | 루트 사용자 |
| 지문 잠금 | MFA |
| 직원 출입증 | IAM 사용자 |
| 지출 알림 | AWS Budgets |

공부 순서는 **도시를 처음부터 짓는 순서**와 같아요.
