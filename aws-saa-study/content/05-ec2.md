AWS의 가장 기본 서비스인 EC2로 가상 서버를 띄우고, 보안 그룹으로 문을 열고 닫고, 접속하고, 요금 방식을 고르는 법을 배웁니다. 구매 옵션(온디맨드, 예약, Savings Plans, 스팟)은 비용 최적화 영역에서 가장 자주 나오는 주제입니다.

@topic c05-ec2 | EC2 기초와 사용자 데이터 | dom=3,4 | prio=3 | les=AWS Budget Setup; EC2 Basics; Create an EC2 Instance with EC2 User Data to have a Website Hands On
**EC2(Elastic Compute Cloud)**는 AWS에서 빌려 쓰는 가상 서버입니다. 실행 중인 서버 한 대를 **인스턴스**라 부르고, 몇 분 만에 만들었다가 필요 없으면 지웁니다. 요금은 실행 중인 시간만큼(리눅스는 초 단위) 냅니다.

#### 인스턴스를 만들 때 고르는 것

| 고르는 것 | 내용 |
|---|---|
| AMI | OS와 기본 소프트웨어가 담긴 틀(Amazon Linux, Ubuntu, Windows) |
| 인스턴스 유형 | CPU, 메모리, 네트워크 성능 규격([5.2](#c05-types)) |
| 스토리지 | 루트 볼륨(EBS) 크기와 종류, 추가 볼륨 |
| 네트워크 | VPC, 서브넷, 공인 IP 여부 |
| 보안 그룹 | 어떤 포트로 누가 들어올 수 있는지([5.3](#c05-sg)) |
| 키 페어 | SSH 접속용 키(리눅스) 또는 관리자 비밀번호 복호화용(Windows) |
| IAM 역할 | 인스턴스 안의 앱이 쓸 권한([4.4](#c04-role)) |
| 사용자 데이터 | 첫 부팅 때 실행할 스크립트 |

#### 사용자 데이터

**사용자 데이터(User Data)**는 인스턴스가 **처음 부팅할 때 한 번** root 권한으로 실행되는 스크립트입니다. 업데이트 설치, 웹 서버 설치, 설정 파일 받기 같은 초기 작업을 자동으로 합니다.

```bash
#!/bin/bash
yum update -y
yum install -y httpd
systemctl enable --now httpd
echo "<h1>Hello from $(hostname -f)</h1>" > /var/www/html/index.html
```

부팅이 느려질 만큼 많은 일을 넣으면 시작 시간이 길어집니다. 매번 같은 소프트웨어를 설치한다면 미리 설치해 둔 AMI(골든 AMI)를 만드는 편이 빠릅니다([11.3](#c11-beanstalk)).

#### 인스턴스 상태

| 상태 | 요금 | 데이터 |
|---|---|---|
| 실행 중(running) | 인스턴스 + EBS | 유지 |
| 중지(stopped) | EBS만 | EBS 유지, 인스턴스 스토어는 사라짐 |
| 최대 절전(hibernated) | EBS만 | 메모리 내용까지 EBS에 저장([6.3](#c06-eni-hibernate)) |
| 종료(terminated) | 없음 | 루트 EBS는 기본으로 삭제 |

> **팁** 강의 5장 첫 레슨은 예산 알림 설정입니다. 실습 계정에서 EC2를 처음 띄우기 전에 [AWS 계정으로 실습하기](#start-lab)의 예산 알림을 먼저 걸어 두세요.

@practice
- **웹·API 서버**: 가장 흔한 쓰임은 Spring Boot, Node.js 같은 백엔드 서버입니다. 운영에서는 한 대만 두지 않고 ALB 뒤에 Auto Scaling 그룹으로 여러 대를 둡니다.
- **사용자 데이터로 자동 설정**: 새 인스턴스가 뜰 때 CloudWatch 에이전트 설치, 배포할 앱 버전 내려받기, 설정 파일 가져오기를 자동으로 합니다. 새벽에 Auto Scaling으로 서버가 늘어나도 사람이 손댈 일이 없습니다.
- **상시 서버**: 매일 밤 도는 정산 배치, 사내 Jenkins·GitLab 서버, VPN 서버처럼 꾸준히 켜 두는 서버도 EC2로 운영합니다.
- **상태 관리로 비용 줄이기**: 개발 서버는 퇴근 시간에 자동으로 중지해 EBS 요금만 내게 합니다. 운영 서버에는 실수로 지우지 않게 종료 방지 옵션을 켭니다.

@easy
EC2는 데이터 센터에 있는 컴퓨터 한 대를 원격으로 빌리는 것입니다. 노트북 렌털과 비슷하지만, 몇 분 만에 받고 시간 단위로 반납할 수 있다는 점이 다릅니다. 만들 때 고르는 AMI, 인스턴스 유형, 스토리지, 네트워크는 컴퓨터를 주문할 때 고르는 운영체제, 사양, 저장 장치, 네트워크 연결에 해당합니다.

사용자 데이터는 새 컴퓨터를 처음 켤 때 자동으로 도는 설치 스크립트입니다. 회사 IT팀이 새 노트북에 업무 프로그램을 일괄 설치하듯, 서버가 뜨자마자 필요한 소프트웨어를 깔고 설정합니다.

중지는 전원을 끄되 디스크는 남겨 두는 것이고, 종료는 컴퓨터를 반납하는 것입니다. 중지 중에는 디스크 보관료만 냅니다.

@topic c05-types | 인스턴스 유형 고르기 | dom=3,4 | prio=3 | rev=1 | les=EC2 Instance Types Basics
**인스턴스 유형**은 CPU, 메모리, 스토리지, 네트워크 성능의 조합입니다. 이름은 `m7g.2xlarge`처럼 **패밀리(m) + 세대(7) + 추가 속성(g) + 크기(2xlarge)**로 읽습니다.

| 이름 부분 | `m7g.2xlarge`에서 | 뜻 |
|---|---|---|
| 패밀리 | `m` | 용도(범용) |
| 세대 | `7` | 숫자가 클수록 최신, 같은 값에 성능이 더 좋음 |
| 속성 | `g` | `g` = AWS Graviton(ARM) 프로세서, `a` = AMD, `i` = Intel, `d` = 로컬 NVMe 디스크, `n` = 네트워크 강화 |
| 크기 | `2xlarge` | 같은 패밀리 안에서 vCPU·메모리 양 |

#### 패밀리별 용도

| 분류 | 패밀리 | 언제 |
|---|---|---|
| 범용 | t, m | 웹 서버, 코드 저장소. CPU·메모리·네트워크가 고르게 필요할 때. `t`는 평소 낮고 가끔 치솟는 부하(버스트) |
| 컴퓨팅 최적화 | c | 배치 처리, 미디어 인코딩, 고성능 웹 서버, 과학 모델링, 게임 서버, 머신러닝 추론 |
| 메모리 최적화 | r, x, z, u | 인메모리 DB·캐시, 대용량 데이터를 메모리에 올려 처리하는 BI, 실시간 빅데이터 처리 |
| 스토리지 최적화 | i, d, h | 로컬 디스크에 대량 읽기·쓰기. OLTP DB, NoSQL, 데이터 웨어하우스, 분산 파일 시스템 |
| 가속 컴퓨팅 | p, g, inf, trn | GPU·전용 칩이 필요한 머신러닝 학습·추론, 그래픽 처리 |
| HPC 최적화 | hpc | 대규모 과학 계산 |

> **후기에서** 2026년 6월 합격 후기는 문제를 풀며 헷갈려 따로 정리한 개념에 *인스턴스 유형*을 넣었습니다. 문제는 "메모리 안에서 대량 데이터를 처리", "초당 수십만 IOPS의 로컬 디스크"처럼 **작업의 성격**을 적고 패밀리를 고르게 합니다. 메모리 → r, CPU → c, 로컬 디스크 → i, GPU → p·g로 연결해 두세요.

비교 사이트 [instances.vantage.sh](https://instances.vantage.sh/)에서 유형별 사양과 가격을 한눈에 볼 수 있습니다.

@practice
- **범용(t·m)**: 트래픽이 적은 사내 관리자 페이지나 개발 서버는 `t` 계열, 꾸준한 트래픽을 받는 API 서버는 `m` 계열이 흔합니다.
- **컴퓨팅 최적화(c)**: 동영상 인코딩, 대량 이미지 변환, 게임 서버, 광고 입찰 서버처럼 CPU를 많이 쓰는 일.
- **메모리 최적화(r·x)**: Redis나 Elasticsearch를 직접 운영하거나, Spark로 대량 데이터를 메모리에 올려 분석할 때.
- **스토리지 최적화(i)**: Cassandra 같은 NoSQL처럼 로컬 NVMe 디스크의 아주 높은 IOPS가 필요한 DB.
- **가속 컴퓨팅(p·g·inf·trn)**: 생성형 AI 모델의 학습과 추론, 3D 렌더링.
- **Graviton으로 옮기기**: 같은 일을 더 싸게 하려고 ARM 기반 Graviton 유형(`m7g`, `c7g` 등)으로 옮기는 회사가 많습니다. Java, Python처럼 런타임 위에서 도는 앱은 큰 수정 없이 옮겨지는 경우가 많습니다.

@easy
인스턴스 유형은 업무용 차량 고르기와 비슷합니다. 영업용 승용차(범용), 힘이 센 트럭(컴퓨팅), 짐칸이 넓은 탑차(메모리), 냉동 창고가 달린 차(로컬 스토리지)처럼 실을 일에 맞춰 고릅니다. 이름의 숫자는 연식, 크기는 배기량에 해당합니다.

`t` 계열은 평소에 CPU를 덜 쓰는 동안 크레딧을 모아 두었다가 바쁠 때 잠깐 세게 쓰는 방식(버스트)입니다. 하루 대부분 한가한 서버에 맞습니다. 꾸준히 바쁜 서버에 쓰면 크레딧을 다 쓴 뒤 느려지거나(표준 모드) 추가 요금이 붙습니다(무제한 모드).

**보안 그룹(Security Group)**은 인스턴스 앞의 가상 방화벽입니다. 어떤 포트로, 어디서 오는 트래픽을 들여보낼지(인바운드), 어디로 나가게 할지(아웃바운드)를 **허용 규칙**으로만 적습니다. 거부 규칙은 없습니다.

#### 동작 규칙

- 처음 만든 보안 그룹은 **인바운드는 모두 막고, 아웃바운드는 모두 허용**합니다.
- **상태 저장(stateful)**입니다. 들어온 요청에 대한 응답은 아웃바운드 규칙과 상관없이 나갑니다.
- 정확히는 인스턴스의 네트워크 인터페이스(ENI)에 붙습니다. 인스턴스 하나에 여러 개, 보안 그룹 하나를 여러 인스턴스에 붙일 수 있습니다.
- 리전과 VPC에 묶여 있습니다. 다른 VPC의 인스턴스에 그대로 쓸 수 없습니다.
- 출발지에 IP 범위 대신 **다른 보안 그룹**을 적을 수 있습니다. "ALB 보안 그룹에서 온 트래픽만 허용"처럼 IP가 바뀌어도 유지되는 규칙을 만듭니다.

#### 접속 문제를 구분하는 법

| 증상 | 원인 |
|---|---|
| 연결이 한참 기다리다 시간 초과 | 보안 그룹(또는 NACL·라우팅)이 막음 |
| 바로 "connection refused" | 트래픽은 도착했지만 앱이 꺼져 있거나 포트를 안 열음 |

#### 외워 둘 포트

| 포트 | 프로토콜 | 쓰임 |
|---|---|---|
| 22 | SSH, SFTP | 리눅스 원격 접속, 파일 전송 |
| 21 | FTP | 파일 전송 |
| 80 | HTTP | 암호화하지 않은 웹 |
| 443 | HTTPS | 암호화된 웹 |
| 3389 | RDP | 윈도우 원격 데스크톱 |
| 3306 / 5432 / 1433 / 1521 | MySQL·MariaDB·Aurora MySQL / PostgreSQL / SQL Server / Oracle | DB 접속([9.7](#c09-elasticache)) |

> **시험 포인트** 3계층 구조에서 DB 보안 그룹의 인바운드 출발지는 **앱 서버의 보안 그룹**으로 적는 것이 정답입니다. `0.0.0.0/0`(전 세계)에 DB 포트를 연 보기는 틀립니다. 보안 그룹은 허용만 있으므로 "특정 IP를 차단"하려면 NACL이나 WAF를 씁니다([29.3](#c29-block-ip)).

@practice
- **3계층 웹 서비스**: ALB 보안 그룹은 인터넷에 80·443을 열고, 앱 서버 보안 그룹은 *ALB 보안 그룹*에서 오는 8080만, DB 보안 그룹은 *앱 서버 보안 그룹*에서 오는 3306만 엽니다. 서버가 늘고 IP가 바뀌어도 규칙을 고칠 필요가 없습니다.
- **관리 접속**: SSH(22)는 사무실 고정 IP나 VPN 대역에만 엽니다. 요즘은 아예 열지 않고 Session Manager로 접속하는 회사가 많습니다.
- **흔한 사고**: 테스트하려고 DB 포트를 `0.0.0.0/0`에 열어 두었다가 외부 스캐너에 발견되는 일이 자주 일어납니다. AWS Config 규칙이나 Security Hub로 이런 규칙을 자동으로 찾아냅니다.
- **장애 대응**: "서버에 연결이 안 된다"는 문의가 오면 시간 초과인지(보안 그룹·네트워크 문제) 연결 거부인지(앱 문제)부터 확인합니다.

@easy
보안 그룹은 서버마다 붙는 출입 허가 명단입니다. "이 포트로, 이 출발지에서 오는 요청만 들여보낸다"를 적어 두고, 명단에 없는 요청은 모두 막습니다. 명단에는 허용만 적을 수 있어서 "이 IP는 차단" 같은 규칙은 만들 수 없습니다.

상태 저장(stateful)이라는 말은 들어온 요청에 대한 응답은 다시 검사하지 않고 내보낸다는 뜻입니다. 그래서 인바운드만 열어도 응답은 나갑니다.

출발지에 다른 보안 그룹을 적는 것은 IP 대신 소속으로 허락하는 방법입니다. "ALB 보안 그룹에 속한 곳에서 온 요청은 통과"라고 적으면 ALB의 IP가 바뀌어도 규칙은 그대로입니다.

@topic c05-connect | SSH, EC2 Instance Connect, 인스턴스 역할 | dom=1 | prio=2 | les=SSH Overview; How to SSH using Linux or Mac; How to SSH using Windows; How to SSH using Windows 10; SSH Troubleshooting; EC2 Instance Connect; EC2 Instance Roles Demo
리눅스 인스턴스에 접속하는 방법은 세 가지입니다. 키 파일로 직접 들어가는 **SSH**, 브라우저에서 키 없이 들어가는 **EC2 Instance Connect**, 포트를 열지 않고 들어가는 **Systems Manager Session Manager**입니다.

| 방법 | 필요한 것 | 22번 포트 |
|---|---|---|
| SSH | 키 페어(.pem), 공인 IP(또는 배스천) | 열어야 함 |
| EC2 Instance Connect | 콘솔 권한. AWS가 일회용 키를 넣어 줌 | 열어야 함(EC2 Instance Connect 대역이나 엔드포인트에서) |
| Session Manager | SSM 에이전트, IAM 역할 | **열지 않음** |

```bash
chmod 0400 my-key.pem                          # 권한이 너무 넓으면 ssh가 거부함
ssh -i my-key.pem ec2-user@<공인 IP>             # Amazon Linux 기본 사용자는 ec2-user
```

SSH가 안 될 때는 보안 그룹의 22번 규칙, 키 파일 권한, 사용자 이름(Amazon Linux는 `ec2-user`, Ubuntu는 `ubuntu`), 인스턴스 재시작으로 바뀐 공인 IP를 차례로 봅니다. **EC2 Instance Connect Endpoint**를 쓰면 공인 IP가 없는 프라이빗 서브넷의 인스턴스에도 브라우저로 들어갈 수 있습니다.

#### 인스턴스 역할

인스턴스 안에서 `aws configure`로 액세스 키를 넣지 않습니다. 대신 **IAM 역할**을 인스턴스에 붙이면(인스턴스 프로파일) 인스턴스 안의 CLI와 SDK가 임시 자격 증명을 자동으로 씁니다([4.4](#c04-role)). 역할을 바꾸거나 떼면 몇 초 안에 반영됩니다.

> **시험 포인트** "SSH 포트를 열지 않고, 배스천 없이, 접속 기록을 남기며 관리하라"면 **Session Manager**입니다([30.2](#c30-ssm)). 인스턴스 안에 액세스 키를 저장하는 보기는 항상 틀립니다.

@practice
- **SSH 키 관리의 어려움**: 팀원이 같은 .pem 키를 돌려 쓰면, 한 명만 퇴사해도 모든 서버의 키를 바꿔야 합니다. 그래서 키 기반 접속을 줄이는 쪽으로 가는 회사가 많습니다.
- **Session Manager**: 금융권처럼 서버 접속 기록을 감사해야 하는 곳은 22번 포트를 닫고 Session Manager로만 접속하게 합니다. 누가 어떤 명령을 쳤는지 S3나 CloudWatch Logs에 남습니다.
- **EC2 Instance Connect Endpoint**: 프라이빗 서브넷의 서버에 들어가려고 배스천 서버를 따로 운영하던 구성을 대신합니다. 배스천의 패치와 비용 부담이 사라집니다.
- **인스턴스 역할**: EC2에서 S3로 백업하기, CloudWatch로 로그 보내기, Secrets Manager에서 DB 비밀번호 읽기를 모두 인스턴스 역할의 권한으로 합니다.

@easy
SSH는 열쇠(키 파일)로 현관문을 여는 방식입니다. 문(22번 포트)이 바깥에 나 있어야 하고, 열쇠가 복사되면 곤란합니다. EC2 Instance Connect는 들어갈 때마다 일회용 열쇠를 받아 쓰는 방식이고, Session Manager는 현관문을 없애고 관리 사무소를 통해서만 들어가는 방식입니다. 관리 사무소가 누가 언제 들어가 무엇을 했는지 기록합니다.

#### 예약 인스턴스와 Savings Plans

- **예약 인스턴스**: 인스턴스 속성(유형, 리전, OS, 테넌시)을 정해 약정합니다. 선결제 없음·일부·전부 중 고르고, 많이 낼수록 할인이 큽니다. **표준**은 할인이 크고, **전환형(Convertible)**은 유형·OS를 바꿀 수 있는 대신 할인이 작습니다(최대 66%). 남는 표준 RI는 RI 마켓플레이스에서 팔 수 있습니다.
- **Savings Plans**: 인스턴스 대신 "시간당 10달러어치를 쓰겠다"는 **금액**을 약정합니다. *EC2 Instance Savings Plans*는 패밀리와 리전을 고정하고(최대 72%), *Compute Savings Plans*는 패밀리, 크기, 리전, OS는 물론 **Fargate와 Lambda**까지 넘나듭니다(최대 66%). 약정을 넘는 사용분은 온디맨드 요금입니다.

#### 스팟 인스턴스

- AWS의 남는 용량을 빌리는 대신, AWS가 용량이 필요하면 **2분 전에 알리고 회수**합니다. 회수 시 중지·최대 절전·종료 중 하나가 일어납니다.
- 중단을 견디는 작업에만 씁니다. DB나 꼭 끝나야 하는 작업에는 쓰지 않습니다.
- **스팟 요청**이 지속형(persistent)이면 회수돼도 조건이 맞을 때 다시 띄웁니다. 스팟 인스턴스를 영구히 없애려면 **요청을 먼저 취소하고** 인스턴스를 종료합니다. 거꾸로 하면 요청이 인스턴스를 다시 만듭니다.
- **스팟 플릿**은 여러 인스턴스 유형·AZ의 스팟(과 온디맨드)을 섞어 목표 용량을 채웁니다. 할당 전략은 가장 싼 풀(`lowestPrice`), 중단이 가장 적은 풀(`capacityOptimized`), 둘을 함께 보는 `priceCapacityOptimized`(권장) 등이 있습니다.

#### 테넌시

| 옵션 | 하드웨어 공유 | 물리 서버 가시성 | 언제 |
|---|---|---|---|
| 기본(공유) | 다른 고객과 공유 | 없음 | 대부분 |

> **시험 포인트** "1년 내내 24시간 돌아가는 DB" → 예약 인스턴스나 Savings Plans. "몇 시간 걸리고 중단돼도 다시 시작할 수 있는 배치" → 스팟. "앞으로 1년 동안 EC2 유형이나 리전이 바뀔 수 있고 Lambda도 쓴다" → Compute Savings Plans. "기존 Oracle 라이선스를 소켓 단위로 가져온다" → 전용 호스트. "특정 AZ에 행사 기간만 용량을 꼭 확보" → 온디맨드 용량 예약.

@practice
- **약정으로 기본 비용 낮추기**: 1년 내내 도는 운영 서버와 DB는 Savings Plans나 예약 인스턴스로 삽니다. 보통 평소 최소 사용량만큼만 약정하고, 그 위로 늘어나는 부분은 온디맨드로 둡니다.
- **스팟으로 배치 비용 줄이기**: 대량 이미지 변환, 머신러닝 학습, CI 빌드, EMR 분석 클러스터처럼 끊겨도 다시 하면 되는 일에 씁니다. 중간 결과(체크포인트)를 S3에 저장해 두면 회수돼도 이어서 합니다.
- **섞어 쓰기**: 웹 서버 Auto Scaling 그룹을 온디맨드 일부 + 스팟 나머지로 섞는 구성(혼합 인스턴스 정책)도 흔합니다.
- **전용 호스트**: Oracle, Windows Server처럼 물리 코어 수로 라이선스를 계산하는 기존 계약을 그대로 쓰려는 회사가 고릅니다.
- **용량 예약**: 티켓 오픈이나 대형 할인 행사 직전에 특정 AZ의 인스턴스 자리를 미리 확보해 둡니다.

@easy
구매 옵션은 숙소를 잡는 방식과 비슷합니다.

- **온디맨드**는 당일 정가로 묵는 것입니다. 언제든 나갈 수 있지만 가장 비쌉니다.
- **예약 인스턴스**는 1년·3년 장기 계약입니다. 객실 종류와 지역을 정하는 대신 크게 할인받습니다.
- **Savings Plans**는 "한 시간에 얼마어치는 쓰겠다"고 금액을 약정하는 회원제입니다. 객실 종류를 바꿔도 할인이 따라옵니다.
- **스팟**은 남는 객실을 아주 싸게 쓰는 대신, 정가 손님이 오면 2분 안에 비워야 하는 조건입니다.
- **전용 호스트**는 건물 한 동을 통째로 빌리는 것이고, **용량 예약**은 할인 없이 방만 맡아 두는 것입니다.

Q: 사용자 데이터 스크립트는 언제, 어떤 권한으로 실행되나요?
A: 인스턴스가 처음 부팅할 때 한 번, root 권한으로 실행됩니다.
Q: 인메모리 캐시 서버로 쓸 인스턴스 패밀리는?
A: 메모리 최적화(r, x 등)입니다.
Q: 웹 서버에 접속하면 한참 기다리다 시간 초과가 납니다. 가장 먼저 의심할 것은?
A: 보안 그룹(또는 NACL, 라우팅)이 해당 포트를 막고 있는지입니다. 바로 "connection refused"라면 앱 쪽 문제입니다.
Q: DB 인스턴스의 보안 그룹에 앱 서버만 들어오게 하려면 인바운드 출발지를 무엇으로 적나요?
A: 앱 서버에 붙은 보안 그룹 ID입니다. 앱 서버 IP가 바뀌어도 규칙이 유지됩니다.
Q: 22번 포트를 열지 않고 인스턴스에 셸로 접속하며 기록을 남기려면?
A: Systems Manager Session Manager를 씁니다. SSM 에이전트와 IAM 역할이 필요합니다.
Q: 매일 밤 3시간 도는 데이터 변환 작업이 중간에 끊겨도 다시 이어서 할 수 있습니다. 가장 싼 구매 옵션은?
A: 스팟 인스턴스입니다.
Q: 지속형 스팟 요청으로 띄운 인스턴스를 종료했는데 계속 새로 생깁니다. 왜 그런가요?
A: 스팟 요청이 살아 있어서 다시 띄우기 때문입니다. 요청을 먼저 취소한 뒤 인스턴스를 종료해야 합니다.
Q: EC2, Fargate, Lambda를 함께 쓰고 앞으로 인스턴스 패밀리와 리전이 바뀔 수 있습니다. 1년 약정 할인으로 가장 알맞은 것은?
A: Compute Savings Plans입니다.
