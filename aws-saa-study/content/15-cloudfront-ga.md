@part ch15 | CloudFront & AWS Global Accelerator: 전 세계로 빠르게 | 강의 섹션 15 | 15. CloudFront와 Global Accelerator
리전 하나에 있는 앱을 전 세계 사용자가 빠르게 쓰게 하는 두 서비스입니다. 둘 다 AWS의 엣지 로케이션을 쓰지만, CloudFront는 **콘텐츠를 엣지에 캐시**하고 Global Accelerator는 **캐시 없이 트래픽을 AWS 전용망으로 실어 나릅니다**.

@topic c15-cloudfront | CloudFront 기초: CDN, 오리진, OAC | dom=1,3 | prio=3 | les=CloudFront Overview; CloudFront with S3 - Hands On
**CloudFront**는 AWS의 **CDN(콘텐츠 전송 네트워크)**입니다. 전 세계 엣지 로케이션(PoP 750곳 이상)에 콘텐츠를 **캐시**해 사용자 가까이에서 돌려주므로 읽기 성능이 좋아지고 오리진의 부담이 줄어듭니다. 엣지가 앞에 서므로 **Shield Standard로 DDoS를 막고**, **WAF**를 붙여 웹 공격을 거릅니다.

#### 요청 흐름

1. 사용자가 가장 가까운 엣지 로케이션으로 요청합니다.
2. 엣지에 캐시가 있으면(캐시 적중) 바로 돌려줍니다.
3. 없으면 **오리진**에서 가져와 돌려주고, TTL 동안 엣지에 캐시합니다.

#### 오리진(Origin)의 종류

| 오리진 | 설명 |
|---|---|
| **S3 버킷** | 파일 배포와 캐시. **OAC**로 버킷을 CloudFront만 읽게 잠금. CloudFront를 거쳐 S3로 업로드도 가능 |
| S3 정적 웹사이트 | 웹사이트 엔드포인트를 사용자 지정 오리진으로(이때 버킷은 공개) |
| **VPC 오리진** | **프라이빗 서브넷**의 ALB, NLB, EC2를 인터넷에 내놓지 않고 오리진으로(2024년 11월부터) |
| 사용자 지정 오리진(HTTP) | 공개된 ALB, EC2, API Gateway, 온프레미스 웹 서버 등 HTTP로 닿는 모든 백엔드 |

#### OAC(오리진 액세스 제어)

S3 버킷을 공개하지 않고 **CloudFront 배포만 읽게** 하는 방법입니다. 버킷 정책에서 서비스 주체 `cloudfront.amazonaws.com`을 허용하되, `AWS:SourceArn` 조건으로 **우리 배포 하나**만 허용합니다. 예전 방식인 **OAI**를 대신하며, SSE-KMS로 암호화된 객체도 다룹니다. 이렇게 하면 사용자는 S3 URL로 직접 받을 수 없고 CloudFront로만 받습니다.

#### 비공개 콘텐츠: 서명된 URL과 서명된 쿠키

로그인한 사용자에게만 유료 콘텐츠를 주려면 **CloudFront 서명된 URL**(파일 하나)이나 **서명된 쿠키**(여러 파일, 예: 동영상 조각 전체)를 씁니다. S3 미리 서명된 URL이 S3에 직접 가는 링크라면, CloudFront 서명된 URL은 캐시된 엣지를 거쳐 오리진 종류와 관계없이 씁니다.

#### CloudFront와 S3 교차 리전 복제 비교

| | CloudFront | S3 교차 리전 복제(CRR) |
|---|---|---|
| 위치 | 전 세계 엣지 전체 | 복제를 설정한 리전만 |
| 최신성 | TTL 동안 캐시(조금 옛것일 수 있음) | 거의 실시간으로 복사 |
| 어울리는 일 | 어디서나 쓰는 **정적 콘텐츠** | 몇몇 리전에서 지연이 낮아야 하는 **동적 콘텐츠**(읽기 전용) |

#### 요금 줄이기

엣지마다 전송 단가가 다릅니다. **가격 등급(Price Class)**으로 쓸 엣지를 줄입니다. All(모든 리전, 가장 빠름), 200(가장 비싼 일부 리전 제외), 100(가장 싼 리전만)입니다. 2025년 11월에는 CDN, WAF, DDoS 방어 등을 묶어 월 정액으로 내는 요금제(Free, Pro, Business, Premium)도 나왔습니다.

> **시험 포인트** "전 세계 사용자에게 정적 콘텐츠를 낮은 지연으로, 오리진 부하 줄이기" → CloudFront. "S3를 공개하지 않고 CloudFront로만 제공" → OAC + 버킷 정책. "유료 회원에게만 동영상 제공" → CloudFront 서명된 URL·쿠키. "비용을 줄이려 일부 지역 엣지만" → 가격 등급. "웹 공격 차단" → CloudFront + WAF([26.6](#c26-waf)).

@practice
- **정적 자산 배포**: 쇼핑몰·뉴스·SNS 서비스는 이미지, JS, CSS를 S3에 두고 CloudFront로 내보냅니다. 비공개 버킷 + OAC가 표준 구성입니다.
- **동영상 스트리밍**: OTT와 강의 플랫폼은 동영상을 짧은 조각(HLS)으로 나눠 CloudFront로 보내고, 유료 회원만 보도록 서명된 쿠키를 씁니다.
- **대용량 다운로드**: 게임 패치, 앱 설치 파일, 펌웨어 업데이트처럼 많은 사람이 같은 파일을 동시에 받는 배포에 씁니다. 출시일에 몰려도 원본 서버는 거의 부하를 받지 않습니다.
- **보안 관문**: CloudFront에 WAF를 붙여 봇, SQL 인젝션, 과도한 요청을 엣지에서 막고, Shield로 DDoS를 흡수합니다.
- **비용 효과**: 캐시 적중률이 높으면 S3 요청 수와 원본 서버의 데이터 전송이 크게 줄어듭니다.

@easy
CDN은 전국에 둔 지역 물류 거점과 같습니다. 본사 물류 센터(오리진) 한 곳에서 모든 주문을 보내면 먼 지역은 오래 걸리고 본사도 바빠집니다. 잘 팔리는 상품을 지역 거점(엣지)에 미리 갖다 두면 가까운 거점에서 바로 보내고, 본사는 거점에 재고가 떨어질 때만 보내면 됩니다. 거점에 얼마나 오래 둘지가 TTL입니다.

OAC는 본사 창고에 "거점 차량만 출입"이라는 규칙을 거는 것입니다. 개인이 본사 창고로 직접 찾아와도 물건을 내주지 않으니, 모든 손님이 거점을 거치게 됩니다.

@topic c15-cf-origins | ALB·EC2 오리진, 지리적 제한, 캐시 무효화 | dom=1,3 | prio=2 | les=CloudFront - ALB/EC2 as an Origin; CloudFront - Geo Restriction; CloudFront - Cache Invalidation
#### ALB와 EC2를 오리진으로

| 구성 | 보안 그룹 |
|---|---|
| EC2를 바로 오리진으로 | EC2가 **공개**되어 있어야 하고, 보안 그룹은 **CloudFront 엣지 IP 대역**만 허용(관리형 접두사 목록 `com.amazonaws.global.cloudfront.origin-facing` 사용) |
| ALB를 오리진으로 | **ALB는 공개**, 보안 그룹은 CloudFront IP 대역만 허용. 뒤의 EC2는 **프라이빗**이어도 되고 ALB 보안 그룹만 허용 |
| **VPC 오리진** | ALB·NLB·EC2를 **프라이빗 서브넷**에 둔 채 CloudFront만 닿게 함. 공개 IP와 IP 대역 관리가 필요 없음 |

예전에는 "ALB는 공개해야 한다"가 정답이었지만, 2024년 11월부터는 VPC 오리진으로 ALB까지 프라이빗에 둘 수 있습니다. 문제에 "오리진을 인터넷에 노출하지 않고"가 있으면 VPC 오리진을 떠올립니다.

#### 지리적 제한(Geo Restriction)

나라 단위로 접근을 막거나 허용합니다.

- **허용 목록(allowlist)**: 목록의 나라만 접근
- **차단 목록(blocklist)**: 목록의 나라만 차단
- 나라는 외부 Geo-IP 데이터베이스로 판단합니다. 저작권 계약상 특정 나라에서만 콘텐츠를 보여 줘야 할 때 씁니다.

#### 캐시 무효화(Invalidation)

오리진의 파일을 바꿔도 엣지는 **TTL이 끝날 때까지 옛 파일**을 줍니다. 바로 바꾸려면 **무효화**를 만듭니다.

- 모든 파일(`/*`)이나 특정 경로(`/images/*`, `/index.html`)를 지정합니다.
- 무효화된 파일은 다음 요청 때 오리진에서 새로 가져옵니다.
- 매달 경로 1,000개까지는 무료이고 넘으면 경로당 요금이 붙습니다(와일드카드 하나는 경로 하나).
- 자주 바뀌는 파일은 이름에 버전을 넣으면(`app.v2.js`) 무효화 없이 새 파일이 바로 쓰입니다.

> **시험 포인트** "CloudFront 뒤 ALB의 EC2가 CloudFront 외 트래픽을 받지 않게" → 보안 그룹 사슬(CloudFront 접두사 목록 → ALB → EC2) 또는 VPC 오리진. "특정 국가 사용자 차단" → 지리적 제한(더 세밀하게는 WAF 지리 규칙). "배포 후에도 옛 파일이 보임" → 캐시 무효화 또는 파일 이름 버전 관리.

@practice
- **API도 CloudFront 뒤에**: 캐시하지 않는 API도 CloudFront를 앞에 두면 사용자와 가까운 엣지에서 TLS 연결을 맺고 AWS 전용망으로 오리진까지 가서 빨라지고, WAF를 한곳에서 적용할 수 있습니다.
- **오리진 숨기기**: ALB 보안 그룹에 CloudFront 관리형 접두사 목록만 허용하거나, VPC 오리진으로 ALB를 프라이빗 서브넷에 두어 사용자가 CloudFront를 건너뛰고 오리진에 바로 오지 못하게 합니다.
- **지역 라이선스**: OTT나 스포츠 중계처럼 국가별 방영권이 있는 콘텐츠는 허용 목록으로 국가를 제한합니다.
- **배포와 캐시**: 프런트엔드 배포 때는 파일 이름에 해시를 넣고(`app.3f9a2.js`), 매번 바뀌는 `index.html`만 무효화합니다. 무효화 요금과 시간을 줄이는 흔한 방법입니다.

@easy
오리진은 CloudFront가 원본을 가져오는 곳입니다. S3뿐 아니라 ALB나 EC2 같은 서버도 될 수 있습니다. 이때 오리진이 인터넷에 열려 있으면 누군가 CloudFront를 우회해 바로 들어올 수 있어서, 오리진은 CloudFront에서 오는 요청만 받게 막아 둡니다.

캐시 무효화는 지역 거점에 "그 상품 진열 내리고 본사에서 새로 받아 오라"고 지시하는 것입니다. 처음부터 새 상품에 다른 이름을 붙여 내보내면 지시 없이도 새 상품이 나갑니다.

@topic c15-ga | AWS Global Accelerator | dom=2,3 | prio=3 | les=AWS Global Accelerator - Overview; AWS Global Accelerator - Hands On
리전 하나에 있는 앱에 전 세계 사용자가 공용 인터넷으로 오면, 여러 구간을 거치며 지연과 흔들림(지터)이 생깁니다. **Global Accelerator**는 사용자를 **가장 가까운 엣지 로케이션**으로 받아 그 뒤로는 **AWS 전용망**으로 앱까지 실어 나릅니다.

#### 유니캐스트와 애니캐스트

- **유니캐스트 IP**: 서버 하나가 IP 하나를 가집니다(보통의 경우).
- **애니캐스트 IP**: 여러 곳이 **같은 IP**를 가지고, 사용자는 **가장 가까운 곳**으로 연결됩니다.

#### 동작과 특징

- 가속기를 만들면 **고정 애니캐스트 IP 2개**를 받습니다. 사용자는 이 IP로 접속하고, 가장 가까운 엣지로 들어옵니다.
- 엔드포인트: **탄력적 IP, EC2, ALB, NLB**(공개·프라이빗 모두). 리전마다 **엔드포인트 그룹**을 두고, **트래픽 다이얼**로 리전별 비율을, **가중치**로 엔드포인트별 비율을 정합니다.
- **상태 확인**으로 문제가 생긴 엔드포인트를 빼고 다른 리전으로 바로 넘깁니다. IP가 바뀌지 않으므로 **DNS 캐시나 TTL을 기다리지 않습니다**. 재해 복구에 좋습니다.
- **보안**: 방화벽에 등록할 IP가 2개뿐이고, Shield로 DDoS를 막습니다.

#### CloudFront와 비교

| | CloudFront | Global Accelerator |
|---|---|---|
| 하는 일 | 엣지에서 **콘텐츠를 캐시**해 돌려줌 | 캐시 없이 **패킷을** 엣지에서 리전의 앱까지 **전용망으로 전달** |
| 프로토콜 | HTTP·HTTPS | **TCP·UDP** 모두(게임, IoT, VoIP 등 HTTP가 아닌 것) |
| 접속 주소 | DNS 이름(IP는 바뀜) | **고정 IP 2개** |
| 어울리는 일 | 정적 콘텐츠(이미지, 동영상), 동적 콘텐츠 가속 | 고정 IP가 필요한 앱, 빠른 리전 장애 조치, HTTP가 아닌 트래픽 |

둘 다 AWS 엣지 네트워크를 쓰고 Shield로 보호받습니다.

> **시험 포인트** "전 세계 사용자, UDP 게임 서버, 지연을 줄이고 고정 IP" → Global Accelerator. "고객사 방화벽에 등록할 고정 IP가 필요한 다중 리전 앱" → Global Accelerator(리전 하나라면 NLB 탄력적 IP도 가능). "리전 장애 때 DNS TTL을 기다리지 않고 바로 다른 리전으로" → Global Accelerator. "이미지·동영상 캐시" → CloudFront.

@practice
- **글로벌 게임과 실시간 서비스**: UDP로 통신하는 대전 게임, 화상·음성 통화, IoT 기기 연결처럼 지연과 흔들림에 민감한 서비스가 해외 사용자의 연결 품질을 높이려고 씁니다.
- **B2B 고정 IP**: 고객사 방화벽에 IP를 등록해야 하는 SaaS가 여러 리전에서 서비스하면서도 IP 2개만 알려 줍니다.
- **빠른 리전 전환**: DNS 캐시 때문에 리전 전환이 몇 분씩 걸리는 것이 문제라면, IP가 바뀌지 않는 Global Accelerator로 엔드포인트만 바꿉니다.
- **트래픽 다이얼로 이전**: 새 리전으로 옮길 때 다이얼을 10% → 50% → 100%로 올리며 옮깁니다.

@easy
Global Accelerator는 가까운 고속도로 진입로를 알려 주는 서비스입니다. 사용자는 어디에 있든 같은 주소(고정 IP 2개)로 접속하지만, 실제로는 집에서 가장 가까운 진입로(엣지)로 들어가고, 거기서부터는 막히지 않는 AWS 전용 도로로 목적지 리전까지 갑니다. 목적지가 문을 닫으면 도로가 바로 다른 리전으로 길을 바꾸고, 주소는 그대로입니다.

CloudFront와 다른 점은 물건을 미리 갖다 두지 않는다는 것입니다. CloudFront는 콘텐츠를 엣지에 쌓아 두고 내주고, Global Accelerator는 요청 자체를 빠른 길로 실어 나릅니다.

@quiz
Q: 전 세계 사용자에게 S3의 이미지를 빠르게 제공하면서 S3 버킷은 공개하지 않으려 합니다. 어떻게 구성하나요?
A: S3를 오리진으로 하는 CloudFront 배포를 만들고 OAC를 설정해, 버킷 정책이 그 배포만 읽기를 허용하게 합니다.
Q: 유료 회원에게만 여러 동영상 조각 파일을 CloudFront로 제공하려 합니다. 무엇을 쓰나요?
A: CloudFront 서명된 쿠키입니다(파일 하나라면 서명된 URL).
Q: CloudFront 뒤의 ALB와 EC2를 인터넷에 노출하지 않고 운영하려 합니다. 가장 간단한 방법은?
A: ALB를 프라이빗 서브넷에 두고 CloudFront VPC 오리진으로 연결합니다.
Q: 저작권 계약상 특정 국가에서만 동영상을 볼 수 있어야 합니다.
A: CloudFront 지리적 제한의 허용 목록에 그 국가들을 넣습니다.
Q: 웹사이트의 CSS를 고쳐 S3에 올렸는데 사용자는 여전히 옛 CSS를 받습니다. 바로 고치려면?
A: CloudFront에서 해당 경로를 무효화합니다(또는 파일 이름에 버전을 넣어 배포합니다).
Q: 여러 리전에서 UDP로 동작하는 게임 서버에 전 세계 사용자가 낮은 지연으로 접속해야 하고, 고정 IP가 필요합니다.
A: Global Accelerator입니다.
Q: CloudFront와 Global Accelerator의 가장 큰 차이 하나는?
A: CloudFront는 엣지에 콘텐츠를 캐시하고, Global Accelerator는 캐시 없이 트래픽을 AWS 전용망으로 리전의 엔드포인트까지 전달합니다.
